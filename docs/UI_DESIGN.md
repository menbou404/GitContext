# GitContext UI設計

## 目的

GitContextのGUIを、毎日開いてすぐ作業できる、落ち着いた業務ツールとして作り直す。あわせて、AIクライアントへMCPサーバーを登録する「AI連携」画面と、操作の記録を見る「履歴」画面を追加する。

## 現在のUIの課題

| 課題 | 例 |
|---|---|
| 作業画面の上半分が宣伝ページのよう | 明朝体の大見出し、件数を並べたカード、「MVPでは任意」のような内部用語 |
| よく使う操作が埋もれている | 右パネルに同期・commit・PR作成・PR確認とmerge・push・削除が同じ重みで並び、8種類のダイアログが開く |
| 言葉が揃っていない | 「Identity」と「Profile」が混在。「リポジトリIDENTITY」のような英大文字の見出し |
| 未完成の項目が見える | 「安全ログ（準備中）」がメニューにある |
| 見た目が汎用的 | 濃い緑とクリームの配色、多数のバッジ、カードの中のカード。使えないボタンがエラーのような赤 |

## 原則

1. **道具であって宣伝ページではない。** 見出しや件数カードで飾らず、開いたらすぐリポジトリの一覧と作業に入れるようにする。
2. **色はプロファイルのために取っておく。** 画面は無彩色で組み、色が付くのはプロファイルの色だけ。どのリポジトリがどのアカウントかを色で見分けられるようにする。主ボタンも色ではなく濃い墨色にする。
3. **状態の表し方は1つ。** リポジトリの状態は下記の4種類だけを使い、同じ部品で表示する。
4. **確認してから実行する流れを、画面の中で行う。** 変更前に差分を見せて確認するという安全の考え方は保ち、ダイアログではなく、操作する画面の中に確認の段階を置く。
5. **必要なときだけ知らせる。** 環境の検出結果（git、gh、SSH）は常時表示せず、問題があるときだけ通知する。

## 用語

| 日本語 | 英語 | 使い方 |
|---|---|---|
| プロファイル | Profile | GitHubアカウントとGit作成者・SSH鍵・GitHub CLI認証のまとまり |
| リポジトリ | Repository | GitContextに登録したローカルのGitリポジトリ |
| 割り当て | Assign | リポジトリにプロファイルを結び付けること |
| 適用 | Apply | 割り当てたプロファイルの設定をリポジトリのローカル設定へ書き込むこと |
| GitHub連携 | GitHub connection | プロファイル専用のGitHub CLI認証 |
| AI連携 | AI integration | AIクライアントへのMCPサーバーの登録 |

- 「Identity」は画面に出さない。
- commit、push、pull、merge、fetch、ブランチ、Pull Request（PR）はGitの用語としてそのまま使う。
- 見出しを英大文字だけで書かない。内部の段階名（MVP、Tierなど）を画面に出さない。MCPの「Tier」は画面では「公開する範囲」と呼ぶ。

## リポジトリの状態

| 状態 | 日本語表示 | 英語表示 | 条件 | 次の操作 |
|---|---|---|---|---|
| ready | 適用済み | Ready | プロファイルが割り当て済みで、ローカル設定が一致し、GitHub連携のアカウントも一致 | なし |
| reapply | 要再適用 | Reapply needed | ローカル設定がプロファイルの期待値と一致しない（MCPの`get_repository_status`と同じ判定） | 差分を確認して適用 |
| unassigned | 未割り当て | Unassigned | プロファイルが割り当てられていない | プロファイルを選んで適用 |
| attention | 要確認 | Check needed | GitHub連携が未接続、別のアカウントで認証されている、またはリポジトリのローカル状態を読み取れない | プロファイルのGitHub連携またはローカルのリポジトリを見直す |

状態はアイコンと文字の両方で示し、色だけに頼らない。

## 画面構成

```text
左メニュー           画面
─────────           ────────────────────────────────────────────
リポジトリ     →    一覧 → 詳細（概要 / 変更 / 同期 / Pull Request）
プロファイル   →    一覧 → 編集（Git作成者、SSH鍵、GitHub連携）
AI連携         →    AIクライアントの検出・接続・解除
履歴           →    適用とAIによる操作の記録
設定           →    環境の確認、言語、データの保存先とバックアップ
```

ウィンドウの既定サイズは1280×820、最小1050×680。

### リポジトリ一覧

- 見出し、検索、「リポジトリを追加」（ローカルのフォルダ／GitHubからclone）。
- 状態での絞り込み（すべて／要対応／未割り当て）。「要対応」は要再適用と要確認の合計。
- 表の列: 名前とパス、プロファイル（色の点と名前）、ブランチ、状態、未commitの変更数とpush待ちのcommit数。
- 行を選ぶと詳細へ移る。

### リポジトリ詳細

- 上部: 名前、パス、プロファイル、ブランチ、状態。状態が要再適用・未割り当てなら、その場で適用の確認へ進むボタンを出す。
- タブ:
  - **概要**: 割り当てたプロファイル、ローカル設定の一致状況（作成者、SSH鍵、GitHub連携）、origin。プロファイルの変更と適用の確認もここで行う。
    - 「AIによる操作の自動承認」: 「作業ブランチへのpush」「既定ブランチへのpush」「Pull Requestの作成」「Pull Requestのmerge」「GitHubへの公開」のチェック。既定はすべて外れている。チェックは確認ダイアログなしでその場で保存する。リスクが高い項目（既定ブランチへのpush、merge、公開）には、チェックの横に影響を危険の色で常に表示する（例:「確認なしにmainなどの既定ブランチが変わります」）。設定はGUIからだけ変更でき、AIからは変更できない（[MCP_DESIGN.md](MCP_DESIGN.md)参照）。
  - **変更**: 変更ファイル一覧、commitメッセージ、「commitのみ」「commitしてpush」。実行前に、プロファイル・作成者・ブランチ・送信先を確認欄にまとめて示す。
  - **同期**: fetch、ahead/behind、Fast-forward Pull、push。
  - **Pull Request**: 作成と、開いているPRの確認・merge。
- 「GitContextから削除」は詳細画面の末尾に置き、確認を挟む。

### プロファイル

- 一覧: 名前、色、GitHubアカウント、GitHub連携の状態、割り当てているリポジトリ数。
- 編集: 名前、色、Git作成者の名前とメール、GitHubユーザー名、SSH鍵、GitHub連携（ブラウザ認証）。
- 「AIによる操作の自動承認」: 「このプロファイルでのclone」のチェック。リポジトリの自動承認と同じく、確認ダイアログなしで保存し、AIからは変更できない。

### AI連携

- MCPサーバーの情報: 実行ファイルのパス、バージョン、配布版か開発版か。
- 検出したAIクライアントごとの行（Claude Code、Codex（CLIとDesktopは共通の設定）、Claude Desktop）:
  - 状態: 接続済み／未接続／要修復（登録先の実行ファイルが見つからない、別の版を指しているなど）
  - 公開する範囲、登録名、設定ファイルの場所
  - 操作: 接続、範囲の変更、解除、修復
- Claude CodeのCLIとデスクトップのCodeタブは`~/.claude.json`の登録を共用する。Codeタブ向けに`--trust-client-approval`を付けても、確認画面を表示できるCLIではGitContextの確認画面を使う。
- 接続の流れ（画面の中で行う）:
  1. 公開する範囲を選ぶ（読み取りのみ／ローカルの変更まで／GitHub操作まで）。既定は読み取りのみ。GitHub操作まで広げる場合は注意を表示する。
     - クライアントごとに、GitContextの確認画面（elicitation）を出せるか（対応／非対応／不安定）を表示する。
     - 非対応・不安定なクライアントで「GitHub操作まで」を選んだ場合は、次の警告を出し、「理解しました」にチェックしたときだけ先へ進める。チェックした場合だけ、登録の引数に`--trust-client-approval`を付ける。
       > このクライアントは、GitContextの確認画面を表示できません。GitHub操作の前の確認は、このクライアント自身の確認に任せることになります。クライアントで自動承認を有効にしていると、確認なしにpushやmergeが実行されます。
     - 警告に同意しなかった場合、そのクライアントではGitHub操作は実行されない（MCPサーバーが拒否する）。
  2. 書き込む設定ファイルと、その差分を表示する。
  3. 「バックアップして接続」で、設定ファイルを退避してから該当の項目だけを書き込む。公式のCLIがあればそれを使う。
  4. 接続を確認し、結果を表示する。
- インストーラーからは登録しない（[MCP_DESIGN.md](MCP_DESIGN.md)参照）。インストーラーの最後に「起動後にAI連携を設定する」を置き、チェックするとこの画面を開く。

### 履歴

- MCPの監査ログ（`mcp-audit.jsonl`）と、GUIからのプロファイル適用の記録を時系列で表示する。
- 絞り込み: リポジトリ、プロファイル、操作した主体（GUI／AIクライアント）。

### 設定

- 環境: git、GitHub CLI、SSHの検出結果と対処の案内。
- 言語: 日本語／English。
- データ: 保存先、開発版かどうか、バックアップの一覧と復元の手順。

### 初回起動

空の一覧の代わりに、次の手順を順に案内する。

1. プロファイルを作る
2. GitHubと連携する
3. リポジトリを追加する
4. AI連携を設定する（任意）

## 見た目

### 色

| 用途 | 値 |
|---|---|
| 背景 | `#F6F7F9` |
| 面（表、パネル） | `#FFFFFF` |
| 罫線 | `#E3E6EA` |
| 文字 | `#1B1F24` |
| 補助の文字 | `#5B6470` |
| 主ボタン | 背景 `#1B1F24`、文字 `#FFFFFF` |
| 選択中 | 背景 `#EEF1F4` |
| 適用済み | `#1E7A4C` |
| 注意（要再適用・要確認） | `#9A5B00` |
| 危険（削除、GitHub操作の公開） | `#B42318` |

プロファイルの色は、利用者が選ぶ色（初期候補 `#D8A33F`、`#56A7D9`、`#D97866`、`#8E78D4`、`#5CA989`）をそのまま使い、点と細い帯にだけ用いる。

ダークモードは提供しない。

### 文字

- 本文: `"Yu Gothic UI", "Segoe UI", system-ui, sans-serif`
- パス、ブランチ名、commit ID、設定値: `"Cascadia Mono", Consolas, monospace`
- 大きさ: 画面見出し20px、区分見出し15px、本文14px、補足12px。行間は1.5。

### 部品

- ボタン: 主（墨色）、副（白地に罫線）、危険（赤文字）。押せない状態は灰色にし、赤くしない。
- 状態表示: アイコンと文字。背景の塗りは使わない。
- プロファイル表示: 色の点と名前。必要に応じてGitHubアカウントを添える。
- 確認欄: 実行の直前に、対象と変更内容をまとめて示す枠。主ボタンはこの枠の中に置く。
- 通知: 画面上部に1行。問題の内容と、対処する画面へのリンク。

## 文言のルール

- 状態や結果は短い言い切りで書く（「適用しました」「pushできません: originがありません」）。
- エラーには、原因と次の操作を書く。
- 日本語と英語の両方を用意し、意味をそろえる。

## アクセシビリティ

- 操作できるものは、すべて実際のボタン・リンク・入力欄にし、キーボードで操作できるようにする。
- 文字のコントラストは4.5:1以上にする。
- 状態は色だけでなく、アイコンと文字で示す。

## 実装の進め方

`App.tsx`（約1,800行）を、画面と部品に分けながら段階的に置き換える。`backend.ts`の呼び出しはそのまま使う。

| 段階 | 内容 | 前提 |
|---|---|---|
| UI-1 | 画面の枠（左メニュー、通知）、色と文字の定義、リポジトリ一覧と詳細の概要 | なし |
| UI-2 | 詳細の変更・同期・Pull Requestタブ（既存のダイアログを置き換え） | UI-1 |
| UI-3 | プロファイルの一覧と編集、初回起動の案内 | UI-1 |
| UI-4 | 設定画面 | UI-1 |
| UI-5 | 履歴画面 | MCP段階3（監査ログ） |
| UI-6 | AI連携画面 | MCP段階3〜5 |

UI-1では未実装のタブを表示せず、詳細上部の「操作」から既存ダイアログを開く。プロファイル一覧と既存の編集フォームは新しい枠内に置き、UI-3で作り直す。push待ち件数は、一覧を開くたびにfetchしない既存APIがない間は空欄とする。環境通知からプロファイル画面へ進めるのはgh・SSHの問題で、gitの導入案内先となる設定画面へのリンクはUI-4で追加する。

各段階を1つのPRとし、ブラウザ用プレビュー（デモデータ）でも同じ画面を確認できるようにする。

## 見本

リポジトリ一覧、リポジトリ詳細（変更タブ）、AI連携の3画面の見本を作成し、レビューに使う。見本の内容は架空のデモデータだけで構成する。
